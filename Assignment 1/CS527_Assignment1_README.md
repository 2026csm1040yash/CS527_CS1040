# CS527 – Assignment 1
## Mini-Computer Simulator

## 1. Introduction

This project implements **CS527 Assignment 1**, a small mini-computer simulator written completely in the **C programming language**.

The project is divided into four main software components:

1. **Compiler**
   - Reads a simple user-level program.
   - Converts supported instructions into bytecode.
   - Writes the bytecode into `program.byte`.
   - Prints each generated bytecode instruction on the terminal.

2. **Memory**
   - Loads the generated program bytecode into instruction memory.
   - Loads the input data file into data memory.
   - Writes the modified data memory back to the data file after simulation.

3. **Processor**
   - Contains 256 integer registers.
   - Maintains a program counter (`PC`).
   - Fetches instructions from instruction memory.
   - Executes arithmetic, memory, and data-movement instructions.
   - Stops when opcode `0` is encountered.

4. **Main program**
   - Accepts the program file and data file from the command line.
   - Calls the compiler.
   - Initializes memory.
   - Resets the processor.
   - Runs the fetch/execute loop.
   - Saves the final data memory.

The complete execution flow is:

```text
User Program (.txt)
        |
        v
     compiler
        |
        v
   program.byte
        |
        v
Instruction Memory
        |
        v
     Processor
        |
        v
  Data Memory
        |
        v
Updated Data File
```

# 3. File-by-File Explanation

## 3.1 `main.c`

`main.c` is the entry point of the simulator.

It performs the following steps:

```text
1. Check command-line arguments
2. Compile the source program
3. Initialize instruction/data memory
4. Reset the processor
5. Execute instructions until simulation ends
6. Write updated data to the output file
```

The command-line format is:

```text
compiler.exe <program_file> <data_file>
```

For example:

```powershell
.\compiler.exe .\testcase\sum_of_numbers.txt .\testcase\sum_of_number_data.byte.txt
```

The program requires exactly two arguments after the executable name.

If the user runs:

```powershell
.\compiler.exe
```

the program prints:

```text
Usage: .\compiler.exe <program_file> <data_file>
```

# 4. `compiler.c`

The compiler converts the user-level language into bytecode.

The main function is:

```c
void compile(const char *sourceFile, const char *bytecodeFile)
```

It receives:

```text
sourceFile
    -> input program

bytecodeFile
    -> generated bytecode file
```

The compiler opens the source program using:

```c
fopen(sourceFile, "r")
```

and creates the bytecode file using:

```c
fopen(bytecodeFile, "w")
```

Each source line is then checked using `sscanf()`.

The current compiler supports the following instruction types.

The compiler generates:

```text

```

The general format used by this implementation is:

```text

```

For example:

```text
Read x5, 4
```

generates:

```text
5 5 4 0
```

# 6. WRITE

Syntax:

```text
Write x1, 5
```

The compiler generates:

```text
6 1 5 0
```

The general format is:

```text
6 destination address 0
```

The processor then writes the value from the specified register into the specified data-memory address.

```text
-
*
/
```

## 7.3 Multiplication

Source:

```text
x5 = x1 * x3
```

Bytecode:

```text
3 5 1 3
```

Processor operation:

## 7.4 Division

Source:

```text
x3 = x1 / x2
```

Bytecode:

```text
4 3 1 2
```

The processor checks for division by zero:

```c
if(Register[src2] != 0)
{
    Register[dest] = Register[src1] / Register[src2];
}
```

Therefore, valid test programs should not divide by zero.

# 8. Data Movement

The processor supports opcode `7` for moving a constant into a register.

The processor implementation performs:

```c
Register[dest] = src1;
```

For example, if bytecode is:

```text
7 3 25 0
```

the processor performs:

```text
Register[3] = 25
```

The current compiler source shown in this Assignment 1 package does not generate this instruction from a user-level assignment such as:

```text
x3 = 25
```

because the compiler currently parses only `Read`, `Write`, and register-to-register arithmetic.

Therefore opcode `7` is supported by the processor but is not currently generated by the supplied compiler.

# 9. Opcode Table

The current Assignment 1 implementation uses:

| Opcode | Instruction | Meaning |
|---:|---|---|
| `0` | END | Stop simulation |
| `1` | ADD | Register addition |
| `2` | SUB | Register subtraction |
| `3` | MUL | Register multiplication |
| `4` | DIV | Register division |
| `5` | READ | Read data memory into register |
| `6` | WRITE | Write register value to data memory |
| `7` | DATA MOVEMENT | Load constant into register |

The processor contains a `default` case that reports an invalid opcode.

Example:

```text
Invalid Opcode : 9
```

and terminates the simulation.

---

# 10. Processor Registers

The processor contains:

```c
int Register[256];
```

Therefore it has:

```text
x0
x1
x2
...
x255
```

The registers are represented as C `int` values in this Assignment 1 implementation.

The `reset()` function initializes every register to zero:

```c
for(i = 0; i < 256; i++)
{
    Register[i] = 0;
}
```

It also resets:

```text
PC = 0
end_of_simulation = 0
```

---

# 11. Program Counter

The processor has:

```c
int PC;
```

The PC contains the location of the next instruction to fetch.

Each instruction contains four bytes.

The `fetch()` function reads:

```text
inst[PC]
inst[PC + 1]
inst[PC + 2]
inst[PC + 3]
```

into:

```text
opcode
dest
src1
src2
```

Then:

```c
PC = PC + 4;
```

Therefore the PC advances by four after every instruction.

---

# 12. Fetch Operation

The implementation is:

```c
opcode = inst[PC];
dest   = inst[PC + 1];
src1   = inst[PC + 2];
src2   = inst[PC + 3];

PC = PC + 4;
```

Suppose instruction memory contains:

```text
1 6 1 2
```

at addresses:

```text
100
101
102
103
```

The fetch operation reads:

```text
opcode = 1
dest   = 6
src1   = 1
src2   = 2
```

and then advances:

```text
PC = 104
```

---

# 13. Execute Operation

The `execute()` function uses a `switch` statement.

For opcode `0`:

```c
end_of_simulation = 1;
```

For opcode `1`:

```c
Register[dest] = Register[src1] + Register[src2];
```

For opcode `2`:

```c
Register[dest] = Register[src1] - Register[src2];
```

For opcode `3`:

```c
Register[dest] = Register[src1] * Register[src2];
```

For opcode `4`:

```c
Register[dest] = Register[src1] / Register[src2];
```

For opcode `5`:

```c
Register[dest] = Data[src1];
```

For opcode `6`:

```c
Data[src1] = Register[dest];
```

For opcode `7`:

```c
Register[dest] = src1;
```

# 14. Instruction Memory

The memory module declares:

```c
unsigned char inst[256];
```

This represents instruction memory.

The compiler writes bytecode to:

```text
program.byte
```

The `initialize()` function reads the bytecode file and places the values into:

```c
inst[]
```

The current Assignment 1 implementation loads at most 256 bytes.

# 15. Data Memory

The memory module declares:

```c
unsigned char Data[256];
```

This represents the Assignment 1 data memory.

The input data file is loaded using:

```c
initialize(program_file, data_file)
```

The values are read from the data file and placed into:

```c
Data[]
```

The current implementation loads at most 256 data values.

---

# 16. Data File

A data file contains integer values separated by spaces.

Example:

```text
10 20 30 40 50 0 0 0
```

These values are loaded sequentially:

```text
Data[0] = 10
Data[1] = 20
Data[2] = 30
Data[3] = 40
Data[4] = 50
Data[5] = 0
...
```

Important:

The current Assignment 1 memory implementation treats these as **individual byte values** because `Data` is declared as:

```c
unsigned char Data[256];
```

It does not combine four bytes into one 32-bit memory word.

---

# 17. Finalize

After the simulation completes, `finalize()` opens the data file in write mode:

```c
fopen(filename, "w")
```

and writes all 256 data-memory values.

The output is therefore the updated data memory.

For example, the sum test initially contains:

```text
10 20 30 40 50 0 ...
```

After execution, address 5 contains:

```text
150
```

so the beginning of the output becomes:

```text
10 20 30 40 50 150 ...
```

---

# 18. Program Termination

The compiler always appends:

```text
0 0 0 0
```

to the generated program.

This is the termination instruction.

When the processor fetches opcode `0`, it performs:

```c
end_of_simulation = 1;
```

The main loop then stops.

This gives the execution sequence:

```text
fetch
execute
fetch
execute
...
fetch opcode 0
execute opcode 0
stop
finalize
```

---

# 19. Main Execution Loop

The main program uses:

```c
while (!end_of_simulation)
{
    fetch();
    execute();
}
```

Therefore the processor repeatedly:

```text
FETCH
  |
  v
EXECUTE
  |
  v
Check end_of_simulation
  |
  +---- no ----> FETCH
  |
  +---- yes ---> FINALIZE
```

The `decode()` function is declared in `processor.h`, but the current `main.c` does not call it and the implementation is commented out in `processor.c`.

This matches the current Assignment 1 implementation.


```text

```

```text

```


### 2. No labels

Labels are not implemented.

---

### 3. No branch instructions

There are no conditional or unconditional branch instructions in the current compiler/processor.

---

### 4. No flags

The current Assignment 1 processor does not implement:

```text

N
C
V
```

---

### 5. No square-bracket memory addressing

The current compiler does not recognize:



### 6. Data movement exists in the processor but not the compiler parser

The processor supports opcode 7:


but the current compiler does not parse:

```text

```

---

### 7. Data memory is 256 bytes

The current implementation uses:

```c

```

---

### 8. Instruction memory is 256 bytes

The current implementation uses:

```c
unsigned char inst[256];
```

---

### 9. Decode is not implemented

The `decode()` declaration exists, but the current Assignment 1 execution path uses:

```text
fetch()
execute()
```

directly.

# 44. Why Header Files Are Used

The project has:

```text
compiler.h
memory.h
processor.h
```

Header files contain declarations that allow multiple `.c` files to use the same functions and global variables.

For example, `compiler.h` declares:

```c
void compile(const char *sourceFile, const char *bytecodeFile);
```

`main.c` includes:

```c
#include "compiler.h"
```

so it can call:

```c
compile(...);
```

without defining the function again.

---

# 45. Include Guards

The header files use:

```c
#ifndef
#define
#endif
```

For example:

```c
#ifndef COMPILER_H
#define COMPILER_H

...

#endif
```

This prevents the same header from being included multiple times during compilation.

# 46. Object Files

When Make compiles:

```text
compiler.c
```

it creates:

```text
compiler.o
```

Similarly:

```text
main.c       -> main.o
memory.c     -> memory.o
processor.c  -> processor.o
```

The object files are then linked together to create:

```text
compiler.exe
```

You normally do not edit `.o` files.

They are generated automatically by the compiler.

```text
     |
     v

     |
     v

     |

     |
     v

     |
     v
```

The main supported operations are:

```text

DATA MOVEMENT (processor opcode)
```

The processor uses:

```text
256 registers

opcode
dest
src1
src2
instruction memory
data memory
```

```text
0 0 0 0
```
